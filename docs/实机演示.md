# 实机演示与理解提纲

演示目标是用实际观察解释“谁在何时生成 HTML”。先在项目根目录安装并构建：

```powershell
pnpm install --frozen-lockfile
pnpm build
pnpm start
```

使用终端打印的三个地址。另开终端执行 `pnpm dev`，查看课程要求的 CSR 开发模式。结束服务使用它所在终端的 `Ctrl+C`。

## 1 CSR 页面与原始响应

打开开发服务器地址，确认有十篇文章。右键选择“查看网页源代码”，查找第一篇标题“把一章书读成三个问题”，应找不到。进入 DevTools 的 Elements 面板时却能找到，这是因为 Elements 展示执行 JS 后的 DOM。

在 DevTools Network 面板勾选 Disable cache，刷新页面，搜索 `main.js`，应看到 `/src/main.js` 返回 200。正式构建的 CSR 会请求 `assets/index-*.js`，两者都是浏览器脚本，但名称与开发附加请求不同。

检查代码：`lab1-csr/src/main.js` 获取数据并调用模板，`innerHTML` 赋值发生在浏览器。共享模块并没有提前把正文写入最初的 HTML 响应。

## 2 关闭 JavaScript 后观察

Chrome 打开 DevTools，按 `Ctrl+Shift+P`，搜索 `Disable JavaScript` 并选择，然后刷新。分别观察：

| 页面 | 预期现象 | 原因 |
| --- | --- | --- |
| CSR | 不显示文章 | 空 HTML 需要浏览器 JS 生成正文 |
| SSR | 十篇正文仍在 | 服务器响应已经包含正文 |
| SSG | 十篇正文仍在 | 构建好的文件已经包含正文 |

SSR 与 SSG 的“刷新页面”仍可使用，因为它是 HTML GET 表单。测试完通过命令菜单选择 Enable JavaScript 恢复。这个开关依赖当前 DevTools 状态，切换页面后应确认设置仍然生效。

## 3 重复请求与生成时机

SSR 连续刷新，观察时间和请求计数；代码中 `renderDocument()` 位于 `app.get('/')` 回调内。SSG 连续刷新，构建时间保持不变；其渲染调用位于 `build-ssg.js`，HTTP 静态服务器只读已生成的文件。

如果两次点击发生在同一秒，屏幕上的秒级时间可能相同，不能据此否定重新生成。请求计数和 HTML 内的 `data-generation-id` 可进一步验证。计数是单个进程的内存状态，重启归零。

## 4 更新数据与重新构建

另开终端执行：

```powershell
pnpm demo
```

观察以下输出顺序：

```text
before-change      SSR: 把一章书读成三个问题
before-change      SSG: 把一章书读成三个问题
after-data-change  SSR: 更新实验：先提问，再验证
after-data-change  SSG: 把一章书读成三个问题
after-rebuild      SSG: 更新实验：先提问，再验证
```

这个脚本在单独启动的临时服务中更新内存数据源，并使用临时 SSG 目录。它不会改动正在浏览的正式页面，所以原浏览器标签不随这个脚本变化。原始实验记录保存在 `evidence/content-update.json`。

若要亲自在正式页面修改内容，编辑 `shared/posts.js` 的第一篇标题，然后分别观察：Vite 开发页会热更新；SSR 要重启服务；SSG 要运行 `pnpm --filter lab1-ssg build` 后刷新；CSR 生产页要运行 `pnpm --filter lab1-csr build`。原因是默认 SSR 从模块常量取数据，而模块文件不会因浏览器刷新自动重新加载。

提交前恢复计划保留的内容并重新生成所需证据。不要把修改前后的数据混在同一次报告中。

## 5 现场测量

打开三个生产地址，分别在 Chrome DevTools Lighthouse 中运行 Performance。使用同一设备与节流设置。报告中至少记录 FCP 和 LCP，TBT、CLS 可以作为补充。Network 面板中的传输大小可能包含压缩或缓存影响，报告必须说明计量口径。

自动复现命令：

```powershell
pnpm evidence
pnpm run lighthouse
```

前者重新构建并覆盖 `evidence` 下的截图、响应和指标；后者覆盖 Lighthouse 报告。重新采集会改变时间、生成标识和性能数值，README 中的静态数值需据新结果同步更新。

## 关键代码阅读顺序

1. `shared/posts.js`：文章数据，不包含渲染行为。
2. `shared/render.js`：数据转 HTML；解释文本转义、模板字符串、`map().join()`。
3. `lab1-csr/src/main.js`：浏览器调用同一模板并设置 DOM。
4. `lab1-ssr/server.js`：请求回调调用模板并发送 HTML。
5. `lab1-ssg/build-ssg.js`：构建时调用模板并写文件。

能够说明这五个文件的关系，再理解 `scripts/demo-update.js` 中的受控实验即可。测量脚本是取证工具，不改变三种页面的核心原理。
