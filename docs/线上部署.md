## 实际配置

| 配置项 | CSR | SSR | SSG |
| --- | --- | --- | --- |
| 服务名称 | `k1kyu-exp1-csr` | `k1kyu-exp1-ssr` | `k1kyu-exp1-ssg` |
| 服务类型 | Static Site | Web Service，Node | Static Site |
| 套餐 | 免费静态托管 | Free，0.1 CPU / 512 MB，Singapore | 免费静态托管 |
| Build Command | `true` | `npx --yes pnpm@11.25.0 install --frozen-lockfile --prod` | `true` |
| Publish Directory | `lab1-csr/dist` | 不适用 | `lab1-ssg/dist` |
| Start Command | 不适用 | `node lab1-ssr/server.js` | 不适用 |
| 环境变量 | `SKIP_INSTALL_DEPS=true` | `NODE_VERSION=24.14.1`、`HOST=0.0.0.0`、`NODE_ENV=production` | `SKIP_INSTALL_DEPS=true` |

CSR 和 SSG 发布的是已提交且已测量的生产产物，`true` 表示本次发布不重新构建，避免生成时间或产物变化后与报告证据不一致。静态服务的托管构建环境自动选择了 Node 26.12.1，但没有执行页面生成脚本；本地构建使用 Node 24.14.1。SSR 使用指定的 Node 24.14.1 安装生产依赖，监听 Render 分配的 `PORT`，本次运行端口为 10000。

修改文章或样式后，应在本地重新构建受影响的 CSR/SSG 产物，同步报告中受影响的证据，再推送到部署源并手动发布。SSR 代码变更也需要重新发布服务。

## 免费服务限制

SSR 免费实例在约 15 分钟没有访问后会休眠，下一次请求需要唤醒，可能等待约一分钟。此时先等待服务启动再观察页面；首次等待包含托管平台的启动耗时，不能直接作为 SSR 渲染本身的性能结论。服务重启后，页面中的内存请求计数会归零。CSR 与 SSG 由静态托管提供，不依赖这个 SSR 实例。

三个服务均选择免费方案，没有选择付费实例。后续是否仍可访问也取决于账户状态及平台免费额度和政策；更新发布步骤见 [运行与提交](运行与提交.md)。
