# 运行与提交

## 本地运行

先安装 Node.js 22.19 或更新的 LTS 版本与 pnpm 11.25.0，在本项目根目录执行：

```powershell
pnpm install --frozen-lockfile
pnpm build
pnpm start
```

不要双击 CSR 源码 `index.html` 运行，因为 ES 模块需要 HTTP 服务。三页共用上级 `shared` 目录，运行和提交时保留整个仓库结构，不能只复制 `lab1-ssr` 源码目录。

本机默认端口：CSR 生产 4173，SSR 3000，SSG 8080。组合启动会避开已占用端口；单独启动可按工具参数或 `PORT` 指定端口。只启动其中一项时：

```powershell
pnpm --filter lab1-csr dev
pnpm --filter lab1-ssr start
pnpm --filter lab1-ssg start
```

这些是分别启动的命令，需要不同终端，不是在一个终端中等上一项结束后才能访问下一项。

截图工具优先使用本机 Chrome，其次 Edge；也可以设置 `BROWSER_PATH` 指向 Chromium 可执行文件。没有浏览器时执行 `pnpm exec playwright install chromium`。

## 文件用途

- `README.md` 是实验报告，不需要另写 Word 才能满足任务书。
- `AI 使用声明.md` 必须保留，内容要据本人实际审核情况更新。
- `evidence` 与 `reports` 保存真实证据，提交时一并保留。
- `node_modules` 是安装依赖，不应提交；`pnpm-lock.yaml` 需要提交。
- `lab1-csr/dist` 和 `lab1-ssg/dist` 已包含可发布的静态产物。
- `.local-servers.json` 只记录本机进程与端口，不应提交。

## 提交前本人完成

1. 核对姓名、学号和班级，亲自运行并核对三页与截图。
2. 阅读必答题、代码及实验分析，并核对 AI 使用声明中的分工记录；个人复现时据实记录操作与观察。
3. 若修改代码或数据，重新构建、运行测试和测量，并同步报告数值。
4. 检查 [Gitee 仓库](https://gitee.com/k1kyu/se3306-exp1) 的文件与报告展示。仓库名称 `se3306-exp1` 符合任务书要求的 `*-exp1` 格式。
5. 打开文末三个在线地址确认可访问；SSR 免费服务休眠后，首次打开需要等待启动。

当前项目已配置远程仓库。今后修改内容后，在本地仓库根目录检查并提交：

```powershell
git status
git add .
git commit -m "更新实验一报告"
git push origin main
```

换电脑或使用全新目录时，可在 Gitee 仓库页面下载 ZIP，解压后进入项目根目录，按上面的命令安装依赖并运行。压缩包包含源码、锁文件、报告和实验记录，不包含 `.git` 历史；下载的文件可直接用于本地运行，但不是已经配置好远程地址的 Git 仓库。

## 线上部署

| 模式 | 发布内容 | 运行要求 |
| --- | --- | --- |
| CSR | 构建后的 `lab1-csr/dist` 整个目录 | 静态托管，不上传源码 index.html 代替产物 |
| SSG | 构建后的 `lab1-ssg/dist` 整个目录 | 静态托管，内容修改需重建并重新发布 |
| SSR | 整个项目中的 package 文件、workspace 配置、lab1-ssr、shared 及依赖安装 | Node 服务，不能只上传静态 HTML |

本次使用 Render 免费托管，三个服务均以仓库根目录作为部署上下文。CSR 与 SSG 直接发布已提交的 `dist`，构建命令为 `true`，设置 `SKIP_INSTALL_DEPS=true`。SSR 安装命令为 `npx --yes pnpm@11.25.0 install --frozen-lockfile --prod`，启动命令为 `node lab1-ssr/server.js`，设置 `NODE_VERSION=24.14.1`、`NODE_ENV=production`、`HOST=0.0.0.0`，`PORT` 使用平台分配的值。完整配置和核验结果见 [线上部署](线上部署.md)。

代码与报告提交到 Gitee，Render 从同内容的 [GitHub 部署源](https://github.com/K1kyu/se3306-exp1) 获取代码。当前本地 Git 的 `origin` 指向 Gitee，`deployment` 指向 GitHub。修改页面后，需要重新构建受影响的静态产物并提交，将修改推送至这两个远程仓库，再在 Render 对相应服务选择 `Manual Deploy` 中的 `Deploy latest commit`；本次通过公开仓库 URL 创建服务，未配置自动部署。仅修改报告无需重新发布页面。
